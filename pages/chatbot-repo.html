How it works

Connect a model, then get to work

When you open the Workbench, the first thing you see is a "Connect a model" panel. That is where you pick your AI engine. It is the only setup step.

Bring your own free key (recommended)

Make a free Ollama Cloud account, copy your API key, paste it into the Workbench, pick a model, and click "Connect & start session." Your key is used only for your session and is never saved anywhere. This gives you your own private usage and lets you choose your model.

Or just use the school's default

Leave the key field blank and click "Use default." The Workbench connects using the school's hosted model so you can try it instantly, no account needed. Great for a first look in a department meeting.

Why bring your own key?

Ollama Cloud has a free tier, so your own key costs nothing to start. It means your chats are billed to your own free allowance rather than the school's, and you can pick the model that fits your task. If you would rather not make an account, the school default is always there.

One-time, about 2 minutes

Get your free Ollama Cloud API key

If you want to use your own key, here is the whole process. You only do this once.

  1. Create a free Ollama Cloud account

    Go to ollama.com/signup and sign up. It is free.

  2. Create an API key

    In your account dashboard, create an API key. It will look something like sk-.... Copy it.

  3. Open the Workbench and paste it in

    Open the Workbench, paste your key into the "API key" field in the Connect a model panel, pick a model from the dropdown, and click "Connect & start session."

Keep your key private

Treat your API key like a password. Never paste it into a chat, an email, or a shared file. The Workbench never saves it, it is only used for the session you are in.

Put it to work

Grade a class set with the Rubric Grader

  1. Open the Rubric Grader

    It is the second tab at the top of the Workbench.

  2. Paste your rubric

    A rubric with criteria and performance levels works best, for example: "Criterion 1: Thesis. Exceeding: a clear, arguable, insightful thesis. Meeting: clear and arguable. Approaching: present but vague. Not yet: no thesis." Repeat for each criterion.

  3. Upload one file per student

    Name each file with the student's name, such as jamie-smith.docx. Supported: PDF, Word (.docx), plain text (.txt), Markdown (.md), CSV (.csv). You can also upload a folder as a .zip.

  4. Generate drafted feedback

    The app reads each file, scores it against the rubric, and drafts feedback for every student, offered as one download.

  5. Review everything

    Open each one, edit anything you disagree with, and approve it before it goes to a student. The AI is a drafting assistant, not the grader of record.

Copy-paste ready

Example prompts to get you started

These ship inside the Workbench and can be loaded with one click. Each is a self-contained prompt with [BRACKETS] where you add your specifics.

Output rules shared by every prompt below

Each prompt asks the AI to return a standalone, print-ready HTML document, not markdown. That is so you can open the file in any browser, print it to a PDF, or paste it into Canvas, Google Docs, or a class page without extra formatting. The rules baked into every prompt are: never use em dashes, never use bullet or numbered lists unless asked, use headings and short sentences, use tables for column-like data, and style for clean letter-size printing. Where a different export fits better, the prompt says so and offers it.

Grade a whole class set with your rubric

Use this with the Rubric Grader: paste it in, upload your rubric and student files, and it drafts feedback for every student.

You are an experienced, fair, and supportive teacher. I am going to give
you a rubric and a folder of student work. Grade EVERY student against the
SAME rubric, the one I provide, and do not invent criteria beyond it.

For each student, return all of the following in one clean, printable HTML
document: a clear heading with the student's name or file name, a score or
level for each rubric criterion laid out as an HTML table with one row per
criterion and one column each for the criterion name, the level or score,
and a short note, an overall score or level, and one or two paragraphs of
specific, encouraging feedback that tells the student exactly what they did
well and the one or two things to work on next.

Style the HTML so it prints cleanly to PDF. Use a white background, a
readable font at about 11 to 12 points, and letter-size margins, and add
print rules so a table row is never split across pages. Use headings and
short paragraphs, not bullet lists.

Be honest and do not inflate scores to be kind. If the work is incomplete
or does not address the prompt, say so plainly. Write feedback in the
student's voice level and respect their dignity. Never claim the student
wrote something they did not. Never use em dashes. Do not use bullet points
or numbered lists. You are drafting feedback for a human teacher to review
before it goes to the student.

Write a lesson plan from a standard

You are an expert curriculum designer for [GRADE] [SUBJECT]. I teach about
[NUMBER] students, and the class is [COURSE NAME]. Design a complete
[LENGTH]-minute lesson for this standard: [PASTE STANDARD]. Here is useful
context about my students and this unit: [PASTE CONTEXT].

The lesson must include every one of these parts, each under its own clear
heading:
A clear, measurable learning objective written in student-friendly language.
A 5-minute opening hook that builds curiosity and connects to what students
already know.
15 minutes of direct instruction with concrete examples and non-examples.
A 15-minute guided or independent practice activity where students DO the
thinking, not just watch or listen.
A 5-minute formative check for understanding, so I can see in the moment who
is getting it and who is not.
A 5-minute closing and a short exit ticket.

Differentiate for a student who struggles and a student who is ready for a
stretch. Keep cognitive load low, one clear idea per step. Do not invent
facts or sources. If you are not sure about something, say so rather than
making it up.

Output the entire lesson as one complete, standalone HTML document with
proper opening and closing tags and a style section. Do not use markdown or
code fences. Style it so it prints cleanly to PDF, a white background, a
readable font at about 11 to 12 points, and letter-size margins, with print
rules so a heading is never the last line on a page. Use headings and short
paragraphs, and put anything column-like in an HTML table.

Never use em dashes. Use periods or commas instead. Do not use bullet points
or numbered lists. Write in plain, concrete language with no vague filler.
Format the plan with clear headings I can copy into my planner. At the very
end, add one line in plain text telling me to open the HTML file in my
browser, choose File, Print, Save as PDF, or paste it into Canvas or Google
Docs.

Draft feedback for one student's writing

You are a supportive writing teacher. Here is a piece of student writing:
[PASTE WRITING]. The assignment was: [PASTE ASSIGNMENT]. The student is in
[GRADE].

Write honest, specific feedback that names two things the student did well,
each with a specific example from their text, names the ONE most important
thing to improve, with a concrete strategy they can use, and ends on an
encouraging note. Keep it to about 150 words. Match the tone to a respectful
peer coach, not a judge. Do not invent praise or point to things that are
not in the text.

Output the feedback as one complete, standalone HTML document with proper
tags and a style section. Do not use markdown or code fences. Structure it
as a small printable feedback slip with a clear heading, the student's
initials or ID in a bracketed placeholder [ ], the body copy in short
paragraphs, and the next step in its own short paragraph. Style it to print
cleanly to PDF on letter-size paper.

Never use em dashes. Do not use bullet points or numbered lists. This is a
draft for me to edit before sharing. At the very end, add one line in plain
text telling me to open the HTML file in my browser and choose File, Print,
Save as PDF, or paste it into my feedback tool.

Differentiate an assignment for three readiness levels

Here is an assignment: [PASTE ASSIGNMENT]. I teach [GRADE] [SUBJECT] with
about [NUMBER] students, some of whom read below grade level and some who
are ready for deeper challenge. The core learning goal is: [PASTE LEARNING
GOAL].

Create three versions of this same task, all on the same topic and all aimed
at that same core learning goal. Do not lower the standard in any version,
change the path and the support, never the bar.

Version A, Support level, for a student who needs more scaffolding and a
smaller cognitive load. Simplify the vocabulary, break the task into smaller
steps, add sentence starters, and reduce the number of choices to make.
Version B, Core level, the standard version most students complete.
Version C, Stretch level, for a student ready for deeper challenge, with
deeper questions or open-ended extension.

For each version, state what stays the same, what changes, and why. Then
present the three versions side by side in one HTML table, one version per
column, so the scaffolding differences are visible at a glance.

Output one complete, standalone HTML document with proper tags and a style
section. Do not use markdown or code fences. Style it to print cleanly to
PDF, a white background, a readable font at about 11 to 12 points, and
letter-size margins, with print rules so a table row is never split across
pages.

Never use em dashes. Do not use bullet points or numbered lists. At the very
end, add one line in plain text telling me to open the HTML file in my
browser and choose File, Print, Save as PDF, or paste it into Canvas or
Google Docs.

Turn a vague assignment into a clear rubric

You are an expert in standards-based grading. Here is an assignment or
learning goal: [PASTE ASSIGNMENT]. The subject is [SUBJECT] and the grade
level is [GRADE].

Build a clear, usable rubric with 3 to 5 criteria that cover the important
parts of the assignment. For each criterion, give 4 performance levels with
descriptions written in language a student can understand: Exceeding,
Meeting, Approaching, and Not yet. Make each level description specific and
observable, not vague adjectives, so I could look at a student's work and
tell, without guessing, which level it meets. Then add a one-line note on
how I might give useful feedback when a student lands at each level.

Present the rubric as one clean HTML table. Rows are the criteria, columns
are the four performance levels, and add a blank column on the far right
where I can record a student's level. Keep the table readable on one printed
page if possible.

Output one complete, standalone HTML document with proper tags and a style
section. Do not use markdown or code fences. Style it to print cleanly to
PDF, a white background, a readable font at about 11 to 12 points, and
letter-size margins, with print rules so the table does not break awkwardly
across pages.

Never use em dashes. Do not use bullet points or numbered lists. Do not
invent standards or requirements beyond what I gave you. At the very end,
add one line in plain text telling me to open the HTML file in my browser
and choose File, Print, Save as PDF, or that I can ask for a CSV file to
import into a spreadsheet.

Build a quiz from your notes or a chapter

You are a test writer for [GRADE] [SUBJECT]. Using the material below,
create a 10-question assessment: 4 multiple-choice questions, 3 short-answer
questions, 2 application questions that ask students to use the idea in a
new situation, and 1 question that asks students to explain their reasoning.
Keep language clear and fair, avoid trick questions, and make sure every
question is answerable only from the material I give you. Do not invent
facts, terms, or sources beyond that material. Here is the material:
[PASTE NOTES OR CHAPTER].

Output the quiz as one complete, standalone HTML document with proper tags
and a style section. Do not use markdown or code fences. Present each
question under its own number as a clear heading, since that is how students
reference them, with the answer options laid out one per line for the
multiple-choice questions, and room to write for the short-answer and
reasoning questions. Put the answer key on a separate page (a new page
break) so it prints separately, as an HTML table with one row per question,
the question, the answer, and a short explanation. Style the whole thing to
print cleanly to PDF on letter-size paper.

Never use em dashes. Do not use bullet points for the question text; number
the questions and lay the multiple-choice options one per line. At the very
end, add one line in plain text telling me to open the HTML file in my
browser and choose File, Print, Save as PDF, or that I can ask for a CSV
version to import into a quiz tool.

Write a parent email that is warm and clear

You are a warm, professional teacher writing to a parent. Draft a short
email under 180 words that opens with a positive, specific observation about
the student, states one area for growth honestly but kindly, proposes a next
step and invites partnership, and ends with warmth and an open door. Fill in
these details: student [NAME], subject [SUBJECT], the positive
[OBSERVATION], the concern [CONCERN], and the suggested next step [NEXT
STEP]. Do not invent information I did not give you. Write in a voice I can
send after light editing. Offer two slightly different openings and let me
pick.

Output the email body as complete HTML I can copy into Gmail or Outlook,
with the subject line as a heading and the body in short paragraphs. No
signature block, I will add my own. Output one complete, standalone HTML
document with proper tags and a light style section so it reads like an
ordinary email. Do not use markdown or code fences.

Never use em dashes. Do not use bullet points or numbered lists. At the very
end, add one line in plain text telling me there is no need to print this
one, just open the HTML to preview it, then copy the text and paste it into
Gmail or Outlook.

Privacy & safety

Where your data goes

Your key is never saved

If you paste your own API key, the Workbench uses it only for your current session. It is not stored, not written to a file, and not visible to anyone else.

The hosted app keeps nothing

The hosted instance runs on ephemeral storage, uploads and generated feedback exist only for the life of the request, then disappear. Nothing is kept on the server.

Student data

Never paste real student names, grades, medical info, or other personally identifying information beyond what the assignment itself needs. The district AI policy still applies: confirm any tool against your school or district approved-software list before use.

AI can be biased and can be wrong. Every output you give a student or family must be reviewed by you. You are responsible for the final feedback.

For the privacy-maximalist

Want it fully on your own device?

The same app can run on your own computer, fully offline, with local Ollama, so nothing leaves your machine at all. That is the strongest privacy option, at the cost of a little setup. It is not required, the hosted Workbench above is the easiest path.

Local version

The local version installs Ollama, pulls a small model, and runs the Workbench on http://localhost:5000. If you would like that, ask the site owner for the current local setup guide.
